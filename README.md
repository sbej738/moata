# 같이타 — 택시 동승 부킹 앱

방향이 비슷한 2~3명이 원하는 시간대에 택시 한 대를 함께 예약하고, **구간 분할 방식**으로 각자 탄 거리만큼 요금을 나눠 내는 웹 앱입니다.
FastAPI 서버 + 브라우저 앱으로 되어 있고, 카카오 키가 없어도 데모 모드로 처음부터 끝까지 돌려볼 수 있습니다.

## 빠른 시작 (Windows PowerShell 기준)

Python 3.10 이상이 필요합니다.

```powershell
cd taxi-share
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. macOS/Linux는 `source .venv/bin/activate`만 다릅니다.

## 혼자서 전체 흐름 시연하기

1. **승객** 탭에서 닉네임과 성별을 넣고 시작합니다.
2. 출발지(예: 강원대학교 삼척캠퍼스 정문)와 도착지(예: 삼척역)를 고르고 **동승 요청하기**를 누릅니다.
3. 대기 화면에서 **데모 동승자 3명 만들기** → **지금 매칭 돌리기**를 누르면 동승 제안이 뜹니다. 데모 승객은 자동으로 수락합니다.
4. 제안 화면에서 내 예상 분담액, 타고 내리는 순서, 구간별 분할 그림을 확인하고 **수락하기**를 누릅니다.
5. **기사 시뮬레이터** 탭에서 **배차하고 출발하기** → 지점 도착 버튼을 마지막까지 누른 뒤, 최종 미터 요금(필요하면 통행료와 구간)을 넣고 **운행 끝내고 정산하기**를 누릅니다.
6. 다시 **승객** 탭으로 오면 정산 결과와 다른 분배 방식(탑승 거리 비례, 단독 직행 거리 비례)과의 비교표를 볼 수 있습니다.

오른쪽 위 드롭다운으로 사용자를 바꿔 가며 여러 사람 역할을 해볼 수도 있습니다. **운영** 탭에서는 대기 현황, 매칭 실행, 데이터 초기화를 합니다.

## 카카오 지도·길찾기 연결

키를 넣으면 지도는 카카오맵으로, 경로·구간 거리·예상 택시요금은 카카오모빌리티 길찾기로 바뀝니다.

1. 카카오 디벨로퍼스에서 앱을 만들고 **JavaScript 키**와 **REST API 키**를 확인합니다.
2. 앱의 플랫폼(Web) 설정에 사이트 도메인 `http://localhost:8000`, `http://127.0.0.1:8000`을 등록합니다. 등록하지 않으면 지도 SDK가 로드되지 않습니다.
3. 앱 관리 페이지에서 카카오맵 API를 활성화합니다. 2026년 7월 21일 이후에는 개발자 계정당 처음 활성화한 앱 하나에만 무료 쿼터가 주어지니, 팀이라면 한 계정의 키를 함께 쓰세요.
4. `.env.example`을 `.env`로 복사해 두 키를 채우고 서버를 다시 켭니다.

콘솔의 메뉴 이름과 쿼터 정책은 바뀔 수 있으니 카카오 디벨로퍼스 문서에서 최신 내용을 확인하세요.
길찾기 호출이 실패하면(키 오류, 쿼터 초과 등) 서버 로그에 경고를 남기고 추정값으로 자동 전환합니다.

## 매칭 확률·예상 시간 예측 (Gemini)

매칭을 기다리는 화면에 "마감 전에 동승자를 찾을 확률"과 "예상 대기 시간"을 보여 줍니다(`app/predict.py`).

1. **통계 기본 추정치** — 서버가 항상 계산합니다.
   - n: 지금 대기 중이면서 성별·시간대·출발지·방향 조건을 모두 만족하는 사람 수
   - λ: 과거 같은 시간대(±60분)·같은 방향 요청의 시간당 도착 수. 기록이 적으면 `PRIOR_RATE_PER_HOUR`에 가깝게 평활합니다.
   - p: 과거 동승 제안이 확정까지 간 비율. 기록이 적으면 `PRIOR_ACCEPT`에 가깝게 평활합니다.
   - T: 마감까지 남은 시간(분)

   ```
   P = 1 − (1 − p)^n · e^(−λ·p·T)
   ```
2. **Gemini 보정** — `.env`에 `GEMINI_API_KEY`가 있으면 위 특징값과 기본 추정치를 Gemini에 보내 구조화 출력(JSON)으로 확률, 예상 시간, 이유, 제안을 받습니다. 서버는 확률을 기본값 ±25%p, 시간을 0~마감 사이로 제한하고, 주 모델이 혼잡(503)하거나 한도를 넘으면(429) 한 번 더 시도한 뒤, 대체 모델(`GEMINI_FALLBACK_MODELS`, 비우면 이 키로 쓸 수 있는 Flash 모델을 자동 조회)로 넘어갑니다. 그래도 실패하면 통계 추정치를 그대로 보여 줍니다. 같은 상황이면 1분 동안 다시 호출하지 않습니다. 연결 상태는 `/api/ai/models`에서 확인할 수 있습니다.

화면 오른쪽 위 표시로 "Gemini 분석"인지 "통계 추정"인지 알 수 있고, "계산 근거 보기"를 펼치면 쓰인 숫자를 모두 볼 수 있습니다.

## 핵심 로직

**매칭** (`app/matching.py`)
1. 값싼 조건부터 거릅니다: 정원(3명) → 같은 성별(중형택시 동승 규정) → 희망 시간대 5분 이상 겹침 → 출발지 1km 이내 → 진행 방향 코사인 유사도 0.7 이상.
2. 탑승이 하차보다 먼저이고 중간에 차가 비지 않는 정차 순서를 모두 만들어(3명이면 60가지), 총 거리가 가장 짧으면서 모두가 `탑승 거리 ≤ (1 + α) × 단독 거리`를 지키는 순서를 고릅니다.
3. 대기 요청을 희망 시작 시각 순으로 보며, 넣었을 때 절감 거리(단독 거리 합 − 그룹 경로 거리)가 가장 많이 늘어나는 그룹에 넣습니다.

매칭 단계의 많은 비교는 직선거리 × 1.3으로만 계산하고, 길찾기 API는 그룹이 정해진 뒤 한 번만 부릅니다.

**정산** (`app/fare.py`)

```
s_i = Σ_{k ∈ 내가 탄 구간} c_k × (내 좌석 수 / 그 구간 탑승 좌석 합),   c_k = F × ℓ_k / L
```

- 같이 탄 구간은 나눠 내고, 혼자 탄 구간은 혼자 냅니다.
- 상한 보장: 각자 몫이 `단독 예상 요금 × (실제 요금 / 예상 요금) × (1 − 10%)`를 넘으면 넘는 금액을 다른 동승자에게 몫 비례로 넘깁니다.
- 통행료는 통행료를 낸 구간의 탑승자끼리만 나눕니다.
- 10원 단위로 내림하고 남는 차액은 대표 결제자(첫 탑승자)에게 붙입니다.

기획서 예시(같은 곳에서 출발, C 3km·B 6km·A 10km 하차, 13,000원)가 A 8,450원, B 3,250원, C 1,300원으로 나오는지 `tests/test_fare.py`에서 확인합니다.

## 상태 흐름

```
요청:  waiting → proposed → confirmed → riding → dropped → done
                 ↘ (거절·마감) waiting        ↘ cancelled / expired
그룹:  proposed → confirmed → riding → completed   (거절·취소 시 cancelled)
```

마감(희망 시간대 끝 10분 전)까지 대기 중이면 미리 고른 방식대로 단독 탑승으로 바꾸거나 요청을 취소합니다.
제안을 거절하면 같은 상대와는 다시 묶지 않습니다. 출발 30분 전부터 확정 그룹을 취소하면 패널티가 1 쌓입니다.

## API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/config` | 지도 종류, 매칭 규칙, 데모 지점 |
| POST | `/api/users` | 사용자 만들기 `{nickname, gender: F/M}` |
| GET | `/api/users/{id}/state` | 진행 중인 요청·그룹, 최근 이용 내역 |
| POST | `/api/quote` | 단독 탑승 예상 거리·요금 |
| POST | `/api/requests` | 동승 요청 |
| POST | `/api/requests/{id}/cancel` | 요청 취소 |
| POST | `/api/match` | 지금 매칭 실행 (`AUTO_MATCH=true`면 30초마다 자동 실행) |
| GET | `/api/groups/{id}` | 그룹 상세(정차 순서, 예상 분담액, 정산) |
| POST | `/api/groups/{id}/accept`, `/reject` | 제안 수락·거절 `{request_id}` |
| POST | `/api/groups/{id}/dispatch`, `/advance`, `/complete` | 기사 시뮬레이터 |
| POST | `/api/reports` | 긴급신고·신고·요금 이의 제기 |
| GET | `/api/overview` | 운영 현황 |
| POST | `/api/demo/seed`, `/api/demo/reset` | 데모 데이터 생성·초기화 |

서버가 켜져 있으면 http://127.0.0.1:8000/docs 에서 직접 호출해 볼 수 있습니다.

## 기획서와 달라진 점, 남은 일

| 기획서 | 이 구현 | 이유 |
| --- | --- | --- |
| Flutter 앱 | 웹 앱(모바일 폭 대응) | 설치 없이 바로 시연하고 테스트하기 위해 |
| PostgreSQL + PostGIS | SQLite | 의존성 없이 실행. 사용자가 많아지면 PostGIS로 반경 검색 |
| WebSocket | 3초 폴링 | MVP 단순화 |
| 휴대폰 본인인증, PG 결제 | 미구현(닉네임·성별 입력, 금액 안내만) | 외부 계약이 필요한 부분 |
| 하차 시 GPS 누적 거리 | 계획 경로의 구간 거리 사용 | 시뮬레이터라 실제 주행 데이터가 없음 |

- 요금표 기본값(서울 중형택시 기준)은 예시값입니다. `.env`에서 강원 지역 요금에 맞게 바꿀 수 있습니다.
- 기본 지역은 강원대 삼척캠퍼스 주변입니다. 다른 지역으로 바꾸려면 `app/demo_places.py`의 지점 목록과 중심 좌표, `app/service.py`의 `SAMCHEOK_PLACES`(데모 요청을 무작위로 만들 지점)를 고치세요.
- 실서비스로 가려면 플랫폼중개사업 등록, 위치기반서비스 신고 등 법적 절차가 필요합니다(기획서 8장).
